# Push Notifications

## Q1: What are Push Notifications?

**Answer:**

Push Notifications are messages sent from a server to a mobile device, even when the application is in the background or completely closed.

They are commonly used to inform users about important updates, reminders, promotions, or alerts.

**Examples:**

- Banking transaction alerts
- Order status updates
- Chat messages
- Promotional offers

**Interview Answer:**

> Push Notifications are server-generated messages delivered to a user's device to notify them about updates, even when the app is not actively being used.

---

## Q2: Why do we use Push Notifications?

**Answer:**

Push Notifications help improve user engagement by delivering timely information.

Common use cases:

- Order Updates
- Payment Confirmation
- OTP Verification
- Chat Messages
- Appointment Reminders
- Promotional Offers

Example:

```text
User Places an Order
        ↓
Server Sends Notification
        ↓
"Your order has been shipped."
```

**Interview Answer:**

> Push Notifications are used to keep users informed, increase engagement, and deliver real-time updates without requiring the user to open the application.

---

## Q3: What are the different types of Notifications?

**Answer:**

There are two main types of notifications:

### 1. Local Notifications

Triggered directly by the application on the user's device.

Examples:

- Medicine Reminder
- Alarm
- Daily Task Reminder

### 2. Push Notifications

Triggered by a remote server and delivered over the internet.

Examples:

- New Chat Message
- Bank Transaction Alert
- Food Delivery Update

**Interview Answer:**

> Notifications are mainly classified into Local Notifications, which are generated by the app itself, and Push Notifications, which are sent from a remote server.

---

## Q4: What is the difference between Local Notification and Push Notification?

**Answer:**

| Local Notification    | Push Notification          |
| --------------------- | -------------------------- |
| Triggered by the App  | Triggered by the Server    |
| Internet Not Required | Internet Required          |
| Device Scheduled      | Sent Remotely              |
| Used for Reminders    | Used for Real-time Updates |

**Example:**

Local Notification:

```text
Reminder:
Drink Water
```

Push Notification:

```text
Your Order has been Delivered.
```

**Interview Answer:**

> Local Notifications are generated by the application itself, while Push Notifications are sent from a remote server using services like Firebase Cloud Messaging (FCM).

---

## Q5: What is Firebase Cloud Messaging (FCM)?

**Answer:**

Firebase Cloud Messaging (FCM) is Google's free cloud messaging service that allows servers to send push notifications to Android, iOS, and Web applications.

Flow:

```text
Server
   ↓
Firebase Cloud Messaging (FCM)
   ↓
Android / iOS Device
```

Features:

- Cross-platform support
- Reliable delivery
- Notification and Data Messages
- Topic-based messaging

**Interview Answer:**

> Firebase Cloud Messaging (FCM) is Google's messaging service that enables developers to send push notifications and data messages to Android, iOS, and Web applications.

---

## Q6: What is Apple Push Notification Service (APNs)?

**Answer:**

Apple Push Notification Service (APNs) is Apple's notification service used to deliver push notifications to iOS devices.

Flow:

```text
Server
   ↓
APNs
   ↓
iPhone / iPad
```

APNs is responsible for:

- Delivering notifications to iOS devices
- Managing notification delivery
- Handling notification security

**Interview Answer:**

> APNs (Apple Push Notification Service) is Apple's official service for delivering push notifications securely to iOS devices.

## Q7: How do Push Notifications work?

**Answer:**

Push Notifications follow a client-server architecture where the server sends a notification through Firebase Cloud Messaging (FCM) or Apple Push Notification Service (APNs), which then delivers it to the user's device.

**Flow:**

```text
User Installs App
        ↓
App Requests Notification Permission
        ↓
FCM/APNs Generates Device Token
        ↓
App Sends Token to Backend Server
        ↓
Server Stores Token
        ↓
Event Occurs (Order Placed, Chat Message, etc.)
        ↓
Server Sends Notification to FCM/APNs
        ↓
FCM/APNs Delivers Notification
        ↓
User Receives Notification
```

**Interview Answer:**

> The app first obtains a device token from FCM or APNs and sends it to the backend server. Whenever an event occurs, the server sends a notification to FCM/APNs using that token, and the notification is delivered to the user's device.

---

## Q8: What is a Device Token?

**Answer:**

A Device Token is a unique identifier generated for a device by the notification service (FCM for Android or APNs for iOS).

It is used by the server to identify the target device for sending notifications.

Example:

```text
Device Token

eYJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**Uses:**

- Identify a device
- Send notifications to a specific device
- Associate a user with a device

**Interview Answer:**

> A Device Token is a unique identifier generated by FCM or APNs that allows the backend server to send push notifications to a specific device.

---

## Q9: What is an FCM Token?

**Answer:**

An FCM Token is a unique registration token generated by Firebase Cloud Messaging for each app installation.

Every Android device (and iOS device using Firebase) receives an FCM token.

Example:

```javascript
import messaging from "@react-native-firebase/messaging";

const token = await messaging().getToken();

console.log(token);
```

Example Output:

```text
eW91ci1mY20tdG9rZW4=
```

**Interview Answer:**

> An FCM Token is a unique registration token generated by Firebase Cloud Messaging. It identifies a specific app installation and is required to send push notifications to that device.

---

## Q10: How is an FCM Token generated?

**Answer:**

The token is generated automatically after:

1. The app is installed.
2. Notification permission is granted (especially on iOS and Android 13+).
3. Firebase is initialized.

Example Flow:

```text
App Installed
      ↓
Firebase Initialized
      ↓
Notification Permission Granted
      ↓
FCM Generates Token
      ↓
App Receives Token
      ↓
Send Token to Backend
```

Example:

```javascript
import messaging from "@react-native-firebase/messaging";

await messaging().requestPermission();

const token = await messaging().getToken();
```

**Interview Answer:**

> Firebase automatically generates an FCM token after the app is installed and notification permission is granted. The app should send this token to the backend server for future notifications.

---

## Q11: What happens when the FCM Token changes?

**Answer:**

An FCM Token can change in situations such as:

- App reinstallation
- User clears app data
- Token refresh by Firebase
- Device restore or migration

When the token changes:

1. The app receives the new token.
2. The old token becomes invalid.
3. The new token must be sent to the backend server.

Example:

```javascript
import messaging from "@react-native-firebase/messaging";

messaging().onTokenRefresh(async (token) => {
  console.log("New Token:", token);

  // Send updated token to backend
});
```

**Flow:**

```text
Old Token
     ↓
Token Refreshed
     ↓
New Token Generated
     ↓
Update Backend
```

If the backend is not updated:

```text
Server
   ↓
Old Token
   ↓
Notification Failed
```

**Interview Answer:**

> FCM tokens can change due to app reinstallations, data clearance, or Firebase token refresh. Whenever the token changes, it should be updated on the backend; otherwise, notifications will fail.

## Q12: How do Push Notifications work in the Foreground?

**Answer:**

When the application is open and actively being used, it is in the **Foreground** state.

By default:

- Android may display the notification depending on implementation.
- iOS does **not** display the notification automatically.

The application receives the notification and can decide how to handle it.

Example:

```javascript id="u8a4v1"
import messaging from "@react-native-firebase/messaging";

messaging().onMessage(async (remoteMessage) => {
  console.log(remoteMessage);
});
```

Flow:

```text id="q1k2pa"
App Open
    ↓
Notification Received
    ↓
onMessage()
    ↓
Show Custom Alert / Update UI
```

**Use Cases:**

- Show an in-app banner
- Update chat messages instantly
- Refresh notifications list

**Interview Answer:**

> In the foreground state, the application receives the notification through the `onMessage()` callback. Developers can choose to display a custom notification or update the UI.

---

## Q13: How do Push Notifications work in the Background?

**Answer:**

When the application is minimized but still running, it is in the **Background** state.

Flow:

```text id="6rlk7u"
App Running in Background
          ↓
Notification Arrives
          ↓
System Displays Notification
          ↓
User Clicks Notification
          ↓
App Opens
```

Handle background notifications:

```javascript id="r3wb6x"
messaging().setBackgroundMessageHandler(async (remoteMessage) => {
  console.log(remoteMessage);
});
```

**Interview Answer:**

> In the background state, the operating system displays the notification. If the user taps the notification, the application opens and developers can handle the event accordingly.

---

## Q14: How do Push Notifications work when the app is Killed (Quit State)?

**Answer:**

Killed State means the application is completely closed and not running.

Flow:

```text id="n7cf2v"
App Closed
      ↓
Notification Received
      ↓
System Displays Notification
      ↓
User Clicks Notification
      ↓
App Launches
```

Handle the initial notification:

```javascript id="k0wv19"
const remoteMessage = await messaging().getInitialNotification();
```

If `remoteMessage` exists, the app was opened by tapping a notification.

**Interview Answer:**

> When the app is in the killed state, the operating system displays the notification. If the user taps it, the app launches, and the notification can be accessed using `getInitialNotification()`.

---

## Q15: How do you handle notification clicks?

**Answer:**

When the user taps a notification, React Native provides callbacks to detect the event.

Example:

```javascript id="v4ie8z"
messaging().onNotificationOpenedApp((remoteMessage) => {
  console.log(remoteMessage);
});
```

Flow:

```text id="oqj1eu"
Notification
      ↓
User Clicks
      ↓
Callback Triggered
      ↓
Navigate to Screen
```

**Interview Answer:**

> Notification clicks are handled using `onNotificationOpenedApp()` when the app is in the background and `getInitialNotification()` when the app is launched from the killed state.

---

## Q16: How do you navigate to a specific screen from a notification?

**Answer:**

Include navigation information inside the notification payload.

Example Payload:

```json id="bqmbd5"
{
  "data": {
    "screen": "OrderDetails",
    "orderId": "12345"
  }
}
```

React Native:

```javascript id="1kljpy"
navigation.navigate(remoteMessage.data.screen, {
  orderId: remoteMessage.data.orderId,
});
```

Flow:

```text id="u0ik2z"
Notification Click
       ↓
Read Payload
       ↓
Navigate to Order Details
```

**Example:**

Notification:

```text id="6gdndz"
Your Order has been Shipped
```

Click:

```text id="zk0mhv"
Order Details Screen Opens
```

**Interview Answer:**

> Navigation is achieved by including screen information in the notification payload and using React Navigation to open the corresponding screen after the notification is clicked.

---

## Q17: How do you pass data inside a notification?

**Answer:**

Data is passed using the **data** payload.

Example:

```json id="r8v0cn"
{
  "notification": {
    "title": "Order Shipped",
    "body": "Track your order."
  },
  "data": {
    "orderId": "12345",
    "status": "Shipped"
  }
}
```

Access the data:

```javascript id="m2obvz"
console.log(remoteMessage.data.orderId);

console.log(remoteMessage.data.status);
```

Output:

```text id="79a71x"
12345

Shipped
```

**Common Data Passed:**

- User ID
- Order ID
- Chat ID
- Product ID
- Screen Name

**Interview Answer:**

> Additional information is passed using the notification's `data` payload, which can be accessed through `remoteMessage.data` and used for navigation or business logic.

| Background | Displayed by OS            | `onNotificationOpenedApp()` |
| Killed     | Displayed by OS            | `getInitialNotification()`  |
